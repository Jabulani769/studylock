# 07 — ADHD-Friendly UX Principles

## Core rule
ADHD support is a product requirement, not a theme or optional setting.

## Reduce executive-function load
- StudyLock chooses the module, topic and next activity automatically.
- The home screen answers: “What do I do now?”
- Show one primary action at a time.
- Keep setup progressive; do not demand every syllabus and timetable on day one.
- Avoid long forms and unnecessary confirmation loops.
- Use sensible defaults, with clear correction paths.

## During a session
- One primary objective.
- Short, concrete instructions.
- Visible progress and predictable transitions.
- Breaks are planned and bounded.
- Attention reset is normal, not failure.
- Resume where the student left off.
- Simple, explicit emergency exits; no multi-stage confirmation loops, puzzles or hold gestures, so exiting never punishes the student.
- Avoid unnecessary animations, sounds, badges and competing indicators.

## Language and motivation
Use neutral, supportive language:
- “Let's return to the next step.”
- “This topic needs another pass.”
- “Your plan has been adjusted.”
Avoid:
- “You failed.”
- “You wasted time.”
- “You broke your streak.”
- punitive debt counters or shame-based warnings.

## Visual accessibility
- Strong readable contrast.
- Scalable typography.
- Large touch targets.
- Clear visual hierarchy.
- Avoid dense dashboards during active study.
- Support TalkBack and system font scaling.
- Motion and sound should be optional and restrained.

## Progress feedback
Distinguish:
- studied = exposure/learning activity recorded;
- understood = reasonable understanding demonstrated;
- mastered = retained knowledge demonstrated repeatedly.
Do not inflate progress simply to motivate.

## Screen design gate
Before UI coding, owner must approve a mobile-first screen inventory, navigation, visual direction, color/typography, session interaction, onboarding and permission explanation. See `11-ui-screen-inventory.md`.
